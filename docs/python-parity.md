# Python 行为对齐与数据库实现

业务规则以本地保留的 `legacy/python/hivesearch` 为基准。Rust 保留 Bot、CLI 与 Web 管理入口；密钥夹、完成记录、分页位置、任务、相册消息定位与会话继续使用加密 SQLite，不恢复为 `.bin` / JSON 工作文件。

| 范围 | 对齐的规则 | 数据库实现 |
| --- | --- | --- |
| 搜索 | 同时读取新消息和原消息编辑；占位提示不作为结果；无结果正常结束；点击末页提示结束；不能仅凭声明总页数停止 | 每页提交，稳定序号；记录当前消息和页号 |
| 翻页异常 | 空回复在当前页局部重试，最多 20 次；普通按钮/等待异常保留已搜结果并给出提示，不从头重发整个任务 | 已保存页不会回滚；提示写入任务报告 |
| 搜索续接 | 优先原消息继续；原消息失效时重新搜索，跳过已保存页 | 保存页号及原消息 ID |
| 领取分组 | “全部获取”后继续“下一组”；按消息 ID 和按钮文字去重；即使显示最后一组也处理按钮；点击后等待首条回复再计算静默窗口 | 收集媒体定位后分块读取，每组最多 10 条，相册完整读取 |
| 领取限流 | 对方文字限流仅在未收到文件时重试当前密钥，最多 5 次；Telegram RPC 限流结束本次任务，由用户决定重试 | 普通超时不自动把整项任务重新排队 |
| 转存与续传 | 空 `start` 回退密钥；保持顺序去重；完成密钥跳过；部分完成按媒体 ID 续传；文件数增加时继续提取；普通失败继续后续项 | 原生完成记录与已导入旧 `state.json` 完成记录均参与判断 |
| 文件与相册 | copy 整组复制；deep 逐文件下载重传；保留文档属性和缩略图，去掉贴纸属性；支持说明、密钥标签、dry-run、redo | 逐文件完成记录、发送意图和临时文件清理 |
| Bot 参数 | 原版搜索页数范围、continue、提取 flags、批量起止序号、续传起点、继承/重做选择 | 批次别名兼容已导入旧文件名；按钮只选本次搜索结果 |
| 标签 | 原版标签分隔规则、说明长度限制、累积去重、10 秒批次窗口；转发相册优先使用带说明的消息补标 | 说明和目标消息映射加密保存 |
| CLI | 搜索默认一页，`--all` 搜全页；支持关键字搜索后提取、指定密钥、范围、说明与标签选项 | CLI 通过常驻服务提交相同业务任务 |

## 离线验证

- 原 Python 的 105 项隔离测试通过；测试使用临时目录与模拟 Telegram 对象。
- `tests/fixtures/python-behavior.json` 保存原版函数输出的 48 个合成样例及源文件 SHA-256，Rust 逐项对照解析、参数、标签、payload 与完成判断。样例没有用户数据。
- Rust 增加数据库升级、旧任务反序列化、完成记录、结果选择范围、按钮所有者和有效期、相册事务测试。
- 使用可注入的领取协议与虚拟时钟，回放最后一组、未知数量、按钮原地编辑、相同 callback 数据、延迟回复、“全部获取”和无后续回复。

离线对照覆盖已列出的规则，不等于真实 Telegram 链路全部验收。此次未启动真实搜索、提取或转发任务；真实账号、目标频道及 0.5 CPU/1GB VPS 资源压测仍未验证。

## 保留的数据库恢复规则

升级时原地添加表和相册分组字段，旧任务缺少的新字段使用兼容默认值。不会删除、重新导入或覆盖现有数据库、原 `.bin` 和旧 Python 文件。

若远端发送结果不确定，发送意图保留并进入 `review`，避免自动重发产生重复文件。这是 Rust 数据库恢复机制，不能声称与 Python 的文件式记录完全相同。明确拒绝的请求会清除未发送意图；已经成功的逐文件完成记录保留。

诊断日志仍由标准输出/journald 记录，`/log` 和管理界面读取数据库任务摘要。Web 管理是新增入口，Python 的交互式终端界面没有原样迁移。
