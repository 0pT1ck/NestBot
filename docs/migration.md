# 迁移约定

原文件已移动到 `legacy/python/`，目录内保持原相对路径。原会话、凭据、JSON、密钥夹及日志未被改写。开发环境 `.venv` 随旧版保留；运行旧版时使用目录内的 python，而非原根目录路径。

Rust 程序使用新的 `config/nestbot.toml`、凭据环境变量和 `.local/` 数据目录。旧 `.env` 不自动读取，避免把旧模式悄悄混入新配置。

`import-legacy PATH` 支持旧 `keys/*.bin` HV1 格式，并导入 `bot.json` 中目标与模式。密码来自 `LEGACY_VAULT_PASSWORD`，未配置时使用 `VAULT_PASSWORD`；命令行不直接传密码。导入重复运行按领取参数去重并保持序号稳定。

公开仓库只包含 Rust 项目。`legacy/python/` 及所有旧数据仅保留在原本的本地工作区，不随仓库发布。新克隆仓库需要导入旧密钥夹时，请自行指定旧版目录；大于 16MiB 的单个密钥夹文件暂不支持。

旧 `state.json` 的匿名进度加密存入 `legacy_claims`，按原 Python 的领取参数参与完成和逐文件续传判断；这不证明其他目标频道已经收到文件。旧账号 StringSession 继续留在旧版，新版需要重新登录；两个版本不要同时用同一账号运行协议任务。

导入时保存旧文件名别名。早期导入没有保存别名的数据库，可以用关键词或批次 ID；旧文件名也能按 Python 的文件名 HMAC 规则匹配，密码先读取 `LEGACY_VAULT_PASSWORD`，未设置时使用新版密钥夹密码。旧、新密码不同时，仅在本地 `secrets.env` 配置旧密码；不会读取或修改旧 `.bin`。

`/batch test progress 11` 将前 11 条标为已转、其余待转，普通续转从第 12 条开始。该设置按批次和数据库稳定序号保存，不改写实际文件完成记录；设置为 0 可重置。后来成功的领取完成记录与批次进度在同一事务提交，避免中断造成重复转存。序号和总条数以新版 `/batch` 显示的数据库条目为准。

批次名称使用主密钥 HMAC 索引，不暴露关键词；条目、任务参数和账号授权密钥使用 XChaCha20-Poly1305 加密，写入数据库前已是密文。主密钥由 Argon2id 派生的密码密钥包裹。现阶段没有密码更换命令，更改解锁环境变量不会重加密已有主密钥。

取消或重启后，已完成的文件按账号、目标、模式及领取项范围去重。单个未完成文件重新下载上传；字节级下载续传和上传分块跨进程恢复尚未实现。
